# House Price Predictor

A full-stack House Price Prediction web app:

- **Frontend:** Next.js 14 + TypeScript + Tailwind CSS (styled after the attached HousePriceAI reference design)
- **Backend:** FastAPI serving a scikit-learn `LinearRegression` model
- **Model:** trained on 3 features — Area (sqft), Bedrooms, Age — to predict Price (in lakhs)

## ⚠️ Important: about the model and data

Your original notebook (`Ml model house pricing.ipynb`) used a hand-typed, 5-row
dataset — not enough to train or evaluate a model meaningfully (the test split
left exactly 1 row, so R² was undefined). At your instruction, I kept the
**exact same model type and 3 features**, but replaced the 5-row dataset with
a **larger synthetic dataset** (600 rows, generated by
`backend/model/train_model.py` with a fixed random seed) that preserves the
same relationship: price rises with area and bedrooms, falls with age.

This means:
- The model and features are faithful to your original logic.
- The dataset is **synthetic, not real listings** — say so if you present this
  as a portfolio project ("trained on a synthetic dataset I generated to
  demonstrate the pipeline" is accurate and still a perfectly good thing to
  show in an interview).
- All metrics shown in the app (R² ≈ 0.96, MAE ≈ ₹6.8L, RMSE ≈ ₹8.3L) were
  computed directly from this training run — see `backend/model/metrics.json`
  — nothing was invented.

If you'd rather train on a real dataset later, replace the data generation
step in `backend/model/train_model.py` with `pd.read_csv("your_data.csv")`
and re-run it; the FastAPI app and frontend don't need to change.

## Deployment architecture

```
 Browser
    │
    ▼
 Vercel (Next.js frontend)
    │  fetch("/predict")  — NEXT_PUBLIC_API_BASE_URL
    ▼
 Render (FastAPI backend, loads house_price_model.joblib)
```

Vercel doesn't run long-lived Python processes, so the FastAPI backend is
deployed separately on **Render** (simplest free option for a small FastAPI
app). The Next.js frontend on Vercel calls it over HTTPS.

## Step-by-step deployment (do these in order)

### 1. Push this project to your GitHub repo

```bash
cd house-price-app
git init
git add .
git commit -m "Add house price predictor app"
git branch -M main
git remote add origin https://github.com/ShubhamLakhwan/Machine_learning.git
# Recommend a NEW repo instead of mixing into your notebooks repo, e.g.:
# git remote add origin https://github.com/ShubhamLakhwan/house-price-predictor.git
git push -u origin main
```

> I'd suggest a dedicated repo (`house-price-predictor`) rather than your
> existing notebooks repo — cleaner for a resume link.

### 2. Deploy the backend on Render

1. Go to render.com and sign in with GitHub.
2. **New → Web Service** → select your repo.
3. Set **Root Directory** to `backend`.
4. Render should auto-detect the `render.yaml` config. If not, set manually:
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
5. Leave `FRONTEND_ORIGIN` blank for now — you'll set it after step 3.
6. Deploy. Once live, copy the URL, e.g. `https://house-price-api.onrender.com`.
7. Visit `https://house-price-api.onrender.com/health` — it should return
   `{"status":"ok","model_loaded":true}`.

   Note: Render's free tier spins down after inactivity, so the first request
   after idle time can take ~30–60 seconds. Fine for a portfolio demo.

### 3. Deploy the frontend on Vercel

1. Go to vercel.com and sign in with GitHub.
2. **Add New → Project** → select your repo.
3. Set **Root Directory** to `frontend`.
4. Add environment variable:
   - `NEXT_PUBLIC_API_BASE_URL` = `https://house-price-api.onrender.com`
     (the Render URL from step 2, no trailing slash)
5. Deploy. Vercel gives you a URL, e.g. `https://house-price-ai.vercel.app`.

### 4. Connect the two (CORS)

1. Back in Render, open your backend service → **Environment**.
2. Set `FRONTEND_ORIGIN` = `https://house-price-ai.vercel.app` (your exact
   Vercel URL from step 3).
3. Save — Render redeploys automatically.

### 5. Test the live app

1. Open your Vercel URL → go to **Predict**.
2. Try a few inputs, e.g.:
   - 1500 sqft, 3 bedrooms, 5 years → should return a price
   - 900 sqft, 1 bedroom, 20 years → should return a lower price
   - 5000 sqft, 6 bedrooms, 0 years → should return a higher price
3. If you get a network/CORS error, double-check `NEXT_PUBLIC_API_BASE_URL`
   (frontend) and `FRONTEND_ORIGIN` (backend) match exactly, with no trailing
   slash, and that Render finished redeploying.

## Running locally

**Backend:**
```bash
cd backend
pip install -r requirements.txt
python model/train_model.py     # only needed if house_price_model.joblib is missing
uvicorn app.main:app --reload
```

**Frontend:**
```bash
cd frontend
npm install
cp .env.local.example .env.local   # leave as localhost:8000 for local dev
npm run dev
```
Visit http://localhost:3000.
